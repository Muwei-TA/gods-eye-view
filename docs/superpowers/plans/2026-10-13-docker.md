# Docker 部署 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供能够服务构建后前端及现有提供方 API 的 Docker Compose 部署。

**Architecture:** 将提供方注册提取为 Vite 和独立 Node 服务共用的接口。部署服务使用 Connect 和静态服务库；多阶段镜像仅保留运行时需要的依赖及资源。

**Tech Stack:** Node 24、Connect、sirv、Docker、Docker Compose、现有 Node 测试。

**Spec:** `docs/superpowers/specs/2026-10-13-zh-cn-docker-design.md`

## Global Constraints

- Node 24.14+（低于 25）；锁定依赖安装。
- 默认 Compose 端口绑定 `127.0.0.1:4173`，容器内监听 `0.0.0.0`。
- 非 root 运行；凭据不进入镜像，私有配置仅通过运行时环境注入。
- 不使用 Vite preview 作为部署服务；保留 Host、CSP、API 校验和清理行为。
- `/api/setup/*` 和远程 MCP 管理入口不注册到部署服务。
- 浏览器公开配置在构建时注入，修改时需重建。

## Review Focus

- 缺少构建产物时应明确失败：任务 1 验证不存在 dist 的启动。
- API 404 不能返回首页：任务 1 请求未知 API 并验证 JSON 状态码。
- 编码路径及恶意 Host 不得泄漏文件：任务 1 验证路径逃逸、dotenv 和 Host 拒绝。
- SIGTERM 不能留下上游连接或计时器：任务 1 验证 dispose 和子进程退出。
- 缓存卷首次创建时非 root 仍可写：任务 2 验证实际容器用户和缓存写入。

### Task 1: 独立部署服务

**Files:**
- Create: `server/standalone/http-server.js`, `server/standalone/start.js`, `server/providers/install.js`, `src/standaloneHttpServer.test.mjs`, `src/providerInstallation.test.mjs`。
- Modify: `server/providers/local.js`, `server/standalone/vite.config.js`, `build/vite.js`, `package.json`, `package-lock.json`。
- Create: `build/browser-headers.js`（从 Vite 构建模块提取部署所需的安全常量）。
- Modify: `scripts/package-boundaries.json`，登记实际共享模块边界。

**Interfaces:**
- `installProviderMiddleware({middlewares, httpServer}, {realtime, deployment}): () => void`，注册共享提供方并返回可重复调用的清理函数；开发专用凭据接口由开发入口单独注册。
- `createDeploymentServer({root, host, port, allowedHosts}): {listen, close}`，返回可启动和关闭的 HTTP 服务；root 是仓库根目录，静态根固定为其 dist。
- `npm start` 执行 `node server/standalone/start.js`，读取 HOST、PORT、GEV_ALLOWED_HOSTS，处理退出信号。
- `GET /healthz` 返回 JSON 成功状态，不请求上游。

- [ ] 编写 HTTP 测试：缺少构建文件、首页和构建资源、未知 API JSON 404、恶意 Host、敏感路径和编码路径拒绝、健康检查、停止清理；使用本地上游夹具验证一条真实提供方链路。
- [ ] 运行 `node --test src/standaloneHttpServer.test.mjs src/providerInstallation.test.mjs`，确认部署接口尚不存在导致失败。
- [ ] 提取公共提供方安装接口和安全头常量，保持 Vite 中间件顺序及 dev-only 设置接口行为；新增独立 HTTP 服务和 CLI。
- [ ] 直接声明运行时 `connect`、`sirv` 和 `ws` 依赖，更新锁文件；不依赖 Vite 的传递依赖进行部署。
- [ ] 运行新增测试、现有提供方/安全相关测试、构建、导入和包边界检查；实际通过 npm start 请求前端和 API。
