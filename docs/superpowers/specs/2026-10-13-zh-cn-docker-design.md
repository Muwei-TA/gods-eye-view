# 简体中文与 Docker 部署设计

日期：2026-10-13

## 目标与已确认方向

用户要求检查简体中文和 Docker 部署支持，补齐缺失功能，并在每个里程碑完成后进行 Git 提交。用户已确认采用以下方向：增加原生中英文语言机制，翻译前端文案，提供保留本地 API 的 Docker 部署。

完成标准是：中文用户能在同一应用内选择简体中文，主要操作、设置和反馈能够用中文理解；用户可以通过 Docker Compose 启动构建后的应用，访问前端和已有数据提供方 API。

默认面向个人及私有环境部署。公网认证、用户账户和多租户隔离不属于本次开发范围。容器默认仅发布到宿主机回环地址；需要公网访问时使用已有反向代理进行认证和 TLS 终止。

## 当前检查结果

- `index.html` 固定声明 `lang="en"`。
- 页面由 `src/ui/templates/*.html` 组成，文案以英文直接写在模板中。
- 前端控制器还会通过 `textContent`、HTML 模板和状态模型生成英文文案；没有统一的语言机制、中文词典或语言偏好入口。
- 应用是 Vanilla JavaScript、Cesium 和 Vite，Node 支持范围为 24.14+（低于 25）或 26。
- 仓库没有 Dockerfile、Compose 或容器部署说明。当前云环境的 Docker 客户端和服务端可用。
- 本地数据、语音和其他提供方 API 通过 `server/providers/` 的中间件提供。仅将 `dist` 放入静态 Web 服务器会丢失这些 API。
- 当前 Vite dev/preview 服务带有 Host 校验、CSP 等策略；文档明确指出 preview 不是生产服务器。
- API 中间件主要依赖 Connect 风格的 `middlewares.use` 和 HTTP 服务的关闭事件，已有 dev 和 preview 的安装入口，可提取共用的注册接口。
- `Provider Settings` 的写入接口是开发专用功能，部署后的应用不能暴露修改服务器凭据的接口。

## 方案选择

采用显式翻译键和轻量语言模块。与通用 DOM 文本替换相比，它能覆盖动态文案并避免误改图标、数据、链接和代码；与引入完整国际化框架相比，更符合现有无框架项目的结构。

容器使用构建产物和独立 Node HTTP 服务，复用已有 API 处理逻辑。Vite 保留为开发和构建工具，容器运行时不以 Vite preview 充当生产服务。

## 语言机制

### 语言选择与存储

- 支持 `en` 和 `zh-CN`。
- 选择优先级：已保存的用户偏好、浏览器语言、英文默认值。
- 浏览器的 `zh`、`zh-CN`、`zh-SG` 和 `zh-Hans` 选择简体中文；其他语言回退英文。繁体中文不声明为已支持的语言。
- 增加始终可访问的语言选择入口，显示 `English` 和 `简体中文`。
- 偏好保存到独立的 localStorage 键；读取或写入失败不阻止应用启动。
- 切换语言保存偏好并重新加载当前 URL。已有分享链接参数保留；不承诺恢复未写入 URL 的临时操作状态。
- 在应用初始化之前设置 `document.documentElement.lang` 并应用静态翻译，避免中文模式启动后仍长时间显示英文。

### 模块职责

- 独立语言核心：语言归一化、偏好解析、词典查询及具名参数插值；可以在 Node 中测试，不依赖浏览器全局对象。
- 英文和简体中文词典：使用稳定语义键；两种词典的键及插值参数保持一致。
- DOM 适配器：仅处理明确标记的文本、`title`、`placeholder`、`aria-label` 等属性；不翻译任意 DOM 节点，不引入 MutationObserver 全局扫描。
- 动态 UI：在生成状态、通知、菜单和模板时调用翻译函数，数字和对象信息通过参数传入。
- 翻译函数返回普通字符串。动态 HTML 继续使用现有转义策略，翻译不得成为新的 HTML 注入入口。
- 缺失中文键回退英文，并通过词典一致性测试发现缺失；不改变业务层的稳定 ID、枚举和协议值。

### 翻译范围

覆盖应用自有的可操作文案：

- 主界面、首次启动引导、加载和失败提示、搜索和导航。
- 地图源、显示控制、风格、图层名称和图层开关说明。
- Context、CCTV、Radio、Street Level、Weather、任务和场景等面板的标题、按钮、空状态及常用状态。
- Provider Settings、语音控制、常见通知和可访问性标签。
- 在 UI 中展示的应用自有说明和错误包装文案。

保留品牌、代码和键名、单位符号、呼号、尾号、第三方数据名称、来源署名、专有地名和用户内容。第三方原始错误可以作为中文错误包装中的详情显示，不宣称翻译任意上游返回文本。服务端日志、MCP 协议和工具标识不随 UI 语言改变；语音模型输出语言不属于本次承诺。

中文 CSS 使用中文系统字体回退，检查按钮宽度、换行、面板标题和移动布局。Material Symbols 的图标文本必须保持原样，避免图标退化为文字。

## 独立部署服务

增加 `npm start` 启动构建后的应用：

1. 校验 `dist/index.html` 存在，未构建时明确失败。
2. 创建 Node HTTP 服务和 Connect 中间件栈。
3. 安装 Host 校验、安全响应头和健康检查。
4. 使用显式共用注册接口安装现有提供方中间件及清理回调，避免复制提供方实现或依赖伪造的 Vite 服务对象。
5. 未识别的 `/api/*` 返回 JSON 404。
6. 静态服务只从 `dist` 读取内容；禁止访问 `.env`、源码、Git 元数据及路径逃逸。不存在的静态资源返回 404。
7. 正常关闭时清理上游连接、定时器和 HTTP 连接；处理 SIGTERM/SIGINT。

使用有明确依赖声明的成熟中间件库处理路由和静态文件，不手写完整 HTTP 静态服务协议。新增运行时依赖更新 `package.json` 和锁文件，使用锁定安装验证。

配置保持当前语义：`HOST`、`PORT` 和 `GEV_ALLOWED_HOSTS`。部署模式关闭开发凭据编辑接口，并默认不注册远程 MCP 管理入口。现有提供方的配额、限流、同站请求校验、目标 URL 校验及错误行为继续生效。

提供 `/healthz`，仅在构建产物和本地服务可用时返回成功，不发出真实数据源或付费 API 请求。上游故障不会把可用的开发/部署环境误判为容器启动失败。

## Docker 与配置

- 多阶段 Dockerfile：Node 24，构建阶段执行 `npm ci` 和 `npm run build`；运行阶段保留明确需要的运行时依赖及提供方需要的资源。
- 将服务端当前需要的 `ws` 等依赖放入运行时依赖范围；Vite、浏览器 QA、图片处理和格式化工具不进入最终运行时安装。
- 使用非 root 用户运行，正确处理终止信号。
- `.dockerignore` 排除 `.git`、`node_modules`、本地构建结果、日志、QA 输出和完整 dotenv 梯度；不得把凭据复制到镜像。
- Compose 默认绑定 `127.0.0.1:4173`，容器内部监听 `0.0.0.0`；提供健康检查和缓存卷。
- 服务端可选密钥通过运行时环境注入，镜像构建不接收私有密钥。
- Google、Cesium、Mapillary 等浏览器公开配置目前在构建时注入。部署文档明确区分公开构建参数与服务端运行时密钥，不承诺运行时修改公开配置无需重建。
- 首次部署不需要任何提供方密钥；缺少可选密钥继续使用已有无密钥路径和提示。
- 文档说明常见出站网络目的地、域名 Host 许可配置、缓存持久化和外部访问方式。

## 里程碑与提交

设计文档单独提交；以下三个功能里程碑分别验证并提交，提交仅包含当前里程碑的变更。

1. **语言基础**：语言核心、双语词典结构、偏好保存、选择入口、模板翻译机制。验证语言归一化、回退、插值、存储失败处理和切换。
2. **中文覆盖**：上述前端自有文案接入、布局调整、中文使用说明。验证中文与英文运行、动态状态、图标和可访问性属性；检查词典完整性。
3. **Docker 部署**：独立服务、提供方共用注册、Dockerfile、Compose、健康检查和部署文档。实际构建并启动容器，验证前端、静态资源、API 和关闭流程。

每次提交前确认工作区变更属于当前里程碑。保留原有英文文案对应行为，必要时更新明确依赖 UI 文本的测试，不为通过测试而删除断言。

## 验证与验收

- 语言核心使用现有 Node 测试方式验证，并检查所有已标记模板键都存在。
- 浏览器检查覆盖英文、简体中文、偏好持久化、动态提示、带参数状态及主要面板，在桌面和窄屏下检查操作可达性。
- 保持现有 build、格式化检查、导入及包边界检查和完整单元测试通过；新增模块按现有边界规则登记。
- 轨迹回归用于检测全局 UI 修改是否影响 Cesium 和实体交互。外部字体、底图网络错误与应用回归分开记录，未完成的检查不计为通过。
- 独立服务测试覆盖正常静态文件、JSON API 404、Host 拒绝、敏感路径拒绝、健康检查和关闭时清理。
- `docker compose build` 和启动成功后请求首页、构建资源及无密钥 API；用可控夹具验证至少一个完整提供方请求及响应形状，避免依赖外部服务稳定性。
- 测试运行时环境注入和容器重启；不调用真实付费 API，不在输出中显示密钥。
- 检查最终镜像中的文件范围和运行用户；确认镜像不包含本地 dotenv、Git 元数据或开发 QA 产物。

当前云环境的字体和底图网络许可草稿尚需用户应用。Docker 拉取镜像若遇到已确认的网络策略阻止，应报告具体目的地并完成不依赖该访问的验证，不关闭 TLS 或依赖校验。

## 明确不包含

翻译外部地图标注和数据提供方内容；改变实体查询或位置搜索协议；自动翻译 AI 输出；新增繁体中文；公网账号体系、认证代理和 Kubernetes 部署。

## 设计自检

目标、语言选择、翻译边界、容器配置和验收标准已明确。开发服务与部署服务的职责分离；公开浏览器配置与私有服务端配置的处理一致；所有功能里程碑都有验证和独立提交要求。
